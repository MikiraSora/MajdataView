SlideDrop 全流程详解

引导星星的出现 · 待机 · 移动 · 判定 · 连续星星接力 — 竖式图表版

一、三个核心时间量

SlideDrop 的所有行为都由三个时间量驱动，赋值位于 JsonDataLoader.cs:1298 附近。理解它们就理解了一切。

timeStart
= timing.Timing：slide 头部那颗 tap 星所在的节拍点时刻，也是判定条轨道"应当完全显示"的时刻。
time
= note.SlideStartTime：引导星星开始移动的时刻。通常晚于 timeStart，中间那段是星星停在起点闪烁的待机时间。
LastFor
= note.SlideTime：引导星星从起点匀速滑到终点的移动时长（时值）。
代码注释原话（SlideDrop.cs:330）：time 是 Slide 启动的时间点，timeStart 是 Slide 完全显示但未启动，LastFor 是 Slide 的时值。

二、单条 Slide 的生命周期（竖式时间轴）

下面按时间从上往下推进。左侧标注的是各关键节点的时刻表达式（相对 timeStart / time，不依赖具体流速）。

timeStart
+ fadeInTime

判定条开始淡入 阶段①

轨道箭头（slideBars）先于星星出现。fadeInTime = -3.926913 / speed（负值，流速 speed 越大绝对值越小）。当 AudioTime − timeStart 到达 fadeInTime 时启用淡入动画。

SlideDrop.cs:188 Initialize() / Update():388

timeStart
+ fullFadeInTime

判定条完全显示

fullFadeInTime = min(fadeInTime + 0.2, 0)。淡入区间 interval = fullFadeInTime − fadeInTime，动画在此区间内把透明度从 0 拉到完全不透明；当 interval 小于 0.2s 时按 animator.speed = 0.2/interval 加快动画挤进去。这一步对应源码注释"8.0 速提前 300ms 显示 Slide"。

timeStart
(节拍点)

引导星星登场 + 待机渐入 阶段②

过了节拍点，star_slide.SetActive(true)。此时 timing = AudioTime − time ≤ 0，星星钉在起点：透明度 alpha = 1 −(−timing)/(time−timeStart) 由 0 渐入到 1，缩放 alpha+0.5 从 0.5 放大到 1.5。break 星此刻起可发光（canShine）。

SlideDrop.cs:398–416

time
(SlideStartTime)

星星起步，开始移动 阶段③

待机结束（待机时长 = time − timeStart）。进入 UpdateStar()，进度 process = min((AudioTime−time)/LastFor, 1) 从 0 到 1，沿预计算路径点 slidePositions 线性插值定位，并按 slideRotations 插值朝向运动方向。移动期间星星恒为白色、缩放 1.5。

SlideDrop.cs:754 UpdateStar()

judgeTiming
= time + LastFor
· CalJudgeTiming()

进入最后判定区 → 正解帧 阶段④

judgeTiming = time + LastFor · CalJudgeTiming()，CalJudgeTiming() 从 0.85 进度往后扫，找星星刚进最后判定区的进度（约 0.85~0.9）作为判定时刻。这一刻决定 Perfect / Great / Good 与 Fast / Late。

SlideDrop.cs:549 Judge() / 634 CalJudgeTiming()

time + LastFor

走到终点

process == 1，星星到达路径末点 slidePositions.Last()。停留时间 stayTime = (time+LastFor) − judgeTiming（进最后判定区到走完的余量）。

arriveTime
+ 0.8·stayTime

销毁并计分

星星到终点后再停留约 stayTime·0.8 才 DestroySelf()。OnDestroy() 显示判定条 slideOK（break 且 Perfect 换 judgeBreakShine 特效），ReportResult() 计入总数与成绩。若超时（> time+LastFor+0.6）则 TooLateJudge：剩 1 区判 LateGood，否则 Miss。

SlideDrop.cs:602 / 708 OnDestroy() / 662 TooLateJudge()

三、判定区与 skip 机制（移动中的判定行为）

judgeQueue 是一串按经过顺序排列的判定区（JudgeArea.cs）。判定并非按时间隐藏箭头，而是按玩家真正划过的进度：划到哪，HideBar 就隐藏到哪根箭头。

单个 Area 的完成条件

区域类型完成条件含义
非最后一个区On && Off要划入再划出（滑过）
最后一个区（IsLast）On只要划入即可

Check() 的连带跳过

每次取队首 first 与下一个 second。当 first.On 或 first.CanSkip 成立，就连带判定 second：

情形结果
second 完成一次跳过 2 个判定区
second 仅 On跳过 1 个判定区
first 完成跳过 first 自己

玩家滑得快时可以跳过中间判定区。SlideDrop.cs:439 Check()

折返点的特例：折线 / V / 圈形（line3 line7 circle3 L*）的折返判定区，其 CanSkip = ConnectInfo.IsConnSlide。即单独出现时不可跳（强制经过折返点），只有作为连续星星一部分时才可跳。SlideDrop.cs:226–245

判定窗口随停留时间动态放大

区间计算
Perfect 基础0.4666667s
Perfect 额外min(stayTime/4, 0.733s)
Great / Good随额外区间增大而收缩

四、连续星星专题：1-2[4:1]s3[4:1]

这类连续 slide 在 JsonDataLoader.cs:1042–1085 被拼装成一个 Slide Group。示例被拆成两段首尾相接的子 slide：

★-2[4:1] · 1→2 直线
2
s3[4:1] · 2→3 的 s 形
3
位置 2 既是第一段终点，也是第二段起点
1

分组与角色标记

isConn = subSlide.Count != 1（此处为 true）。第一段 IsGroupPartHead=true；最后一段 IsGroupPartEnd=true；每段 ConnectInfo.Parent 指向前一段的 GameObject。

2

时间按几何长度重新分配（关键）

LastFor = (TotalLength / TotalSlideLen) · GetSlideLength()。即使两段都写 [4:1]，也按各自实际弧长占整组总长的比例分配时长——目的是让星星在整条路径上匀速滑行。非头部段起始时刻承接前段：time = parent.time + parent.LastFor。

3

星星"接力"，视觉上只有一颗

非头部段待机阶段 alpha = 0，不显示自己的星。前一段星星到终点（process==1）且非组尾时 DestroySelf(true) 只销毁星星，后一段星星紧接着从该点亮起。玩家看到一颗星连贯穿过 1→2→3。

4

整组只结算一次判定

每段最后判定区：组尾 SetIsLast()（只需划入），中间段 SetNonLast()（需划入再划出，作为过渡）。Judge() 开头守卫 if(!IsGroupPartEnd && IsConnSlide) return——只有组尾段（到 3 那段）真正做判定。OnDestroy 中也只有组尾计入总数，中间段直接删判定条不计分。

5

玩家滑得比引导快时

canCheck：头部段到节拍点附近即可判；非头部段要 ParentFinished || ParentPendingFinish 才开判。若某段已被划而前段未完成，Check() 调用 Parent.ForceFinish() 强制完成前一段。链式清理时销毁组尾会连带逐级 Destroy(Parent)。

一句话总结：一条 slide 先在 timeStart + fadeInTime 淡入判定条、timeStart + fullFadeInTime 完全显示，到 timeStart 星星在起点渐入待机，到 time 起步、用 LastFor 匀速滑完路径，在 judgeTiming 附近算判定，走到终点再停留一小段后销毁计分；而 1-2[4:1]s3[4:1] 会被拼成一个 Group——按几何长度重分配各段时长让星星匀速接力穿过，非头段不显示自己的星、中间段只作过渡不计分，整组只结算一次判定。
